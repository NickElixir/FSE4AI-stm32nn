\begin{frame}{What was built}
  \texttt{stm32nn} is a CPU PyTorch extension for the host side of an STM32N657 export.

  \begin{itemize}
    \item The graded operation is \texttt{stm32nn.round\_fp16}.
    \item The same module scores a network and prepares buffers before a flash.
    \item It is packaged as a Linux wheel: \texttt{CppExtension}, six pytest tests, \texttt{make}, \texttt{tools/smoke.sh}, and a two-stage Ubuntu 24.04 image.
  \end{itemize}

  \texttt{smoke.sh} prints \texttt{OK}. \texttt{docker run --rm fse-ops:0.1} prints \texttt{6 passed}.
\end{frame}

\begin{frame}{The network}
  One MNIST CNN, trained 10 epochs on the PC.

  \begin{itemize}
    \item Two \(3\times 3\) convolutions, 32 base channels, two max-pools.
    \item Two linear layers, hidden width 128, dropout 0.25, weight decay \(10^{-5}\).
    \item 421\,642 parameters. Best test accuracy 99.25\%, final test accuracy 99.14\%.
  \end{itemize}

  That checkpoint is the one loaded into the Helium firmware: FP16 weights, FP32 activations.
\end{frame}

\begin{frame}{The graded operation}
  \texttt{round\_fp16} takes a CPU float32 tensor and returns float32 of the same shape.

  Each finite element is rounded to the nearest IEEE binary16 value, ties to even, and stored back in float32. The specification line is
  \[
    \texttt{x.to(torch.float16).to(torch.float32)}.
  \]

  An integer tensor raises \texttt{RuntimeError} from \texttt{TORCH\_CHECK} in the C++ kernel. The six tests cover shape, dtype, an exact value, a value a copy of the input cannot survive, a leading batch of 4, and that error.
\end{frame}

\begin{frame}{What the measurement used}
  \begin{itemize}
    \item \texttt{round\_fp16} cast every parameter of the CNN, then the network ran again in FP32.
    \item \texttt{compare} returns three numbers per pair of logit tensors: mean squared Euclidean gap, fraction of rows whose argmax differs, and mean cosine.
    \item \texttt{to\_nhwc} / \texttt{to\_nchw} match the channel-last buffers of a generated graph.
    \item \texttt{quantize\_per\_channel} is symmetric int8, scale \(\max|w|/127\), codes in \([-127,127]\), returned as float32.
    \item \texttt{check\_export} is empty on this CNN with a zero \(28\times 28\) sample.
  \end{itemize}

  On the first convolution, that int8 rounding moves the weights by a mean square of \(5.05\times 10^{-7}\). That number is a weight change on the PC.
\end{frame}

\begin{frame}{How the board run was made}
  The NUCLEO-N657X0-Q was on the ST-LINK. The Helium weight-only CNN was loaded into RAM and held running.

  \begin{itemize}
    \item MNIST test set, \texttt{numpy} seed 0, 200 images, indices sorted.
    \item Pixels divided by 255, sent as one NCHW float32 image (3136 bytes).
    \item The firmware cycle counter times the kernel. The serial transfer is outside that number.
  \end{itemize}

  The same 200 images were scored on the PC twice: stored FP32 weights, then every parameter passed through \texttt{round\_fp16}. Cube.AI's FP32 graph is the saved serial run of this same subset.
\end{frame}

\begin{frame}{Three scores, one subset}
  \begin{itemize}
    \item Logit MSE: mean over images of \(\|z - z_{\mathrm{FP32}}\|_2^2\). Ten pre-softmax numbers. This is not an average over the 10 classes.
    \item Cosine: mean over images of the cosine between those two vectors.
    \item Label accuracy: fraction of images whose largest logit is the written digit.
  \end{itemize}

  A large squared gap can sit next to a cosine near 1 and next to an unchanged winning class. The table keeps all three.
\end{frame}

\begin{frame}{Results}
  \begin{center}
  \scriptsize
  \begin{tabular}{lrrr}
    \toprule
    Run & Logit MSE & Cosine & Class differs \\
    \midrule
    PC, \texttt{round\_fp16} on the weights & \(2.421720\times 10^{-5}\) & 1.000 & 0/200 \\
    Helium on the board, 20 October & \(2.422037\times 10^{-5}\) & 1.000 & 0/200 \\
    Cube.AI FP32, same 200 images & 5.445340 & 0.998 & 0/200 \\
    \bottomrule
  \end{tabular}
  \end{center}

  \vspace{0.6em}
  Label accuracy is 0.995 on the untouched FP32 network and on all three rows: 199 of 200 digits.

  The eval script's own board file reports \(2.422138\times 10^{-5}\). \texttt{compare} and that file differ in the last digits.
\end{frame}

\begin{frame}{Reading the table}
  \begin{itemize}
    \item FP16 rounding of this CNN moves the logits by about \(2.4\times 10^{-5}\) and changes no class on this subset.
    \item The Helium program, FP16 weights and FP32 activations, lands on that same number.
    \item Cube.AI's FP32 graph moves the logits by 5.445 and still picks the same class on every image. Cosine stays at 0.998.
    \item Label accuracy does not see any of that movement: it is 199/200 for FP32, for the host rounding, for Helium, and for Cube.AI.
  \end{itemize}
\end{frame}
