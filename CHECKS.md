## Почему учебный вариант меньше

**S1 — основной пакет.** Граница: `src/stm32nn/__init__.py`, `ops.cpp`.
Убраны дополнительные conv/pool/linear, int8, layout, compare, export-check и
stochastic API из этого варианта. Их потребители — исследовательские отчёты
и демо, а контракт финального проекта — `round_fp16`. Пользователь подтвердил
сохранение только float32 → float16 → float32. Исходный проект со всеми
функциями сохранён отдельно. Цена старого варианта — отдельные контракты и
непроверенные числовые алгоритмы, не нужные для сдачи. Единственный оставшийся
алгоритм находится в `fp16.h`; Python только экспортирует C++-функцию.
Последствие: исследовательские скрипты нельзя запускать из учебного пакета.
Проверка границы: тесты установленного wheel, exact equality с PyTorch,
ошибка из C++, demo и компиляция общего ядра под Cortex-M55. Риск ограничен
новой самостоятельной копией; восстановление — исходная папка или Git.
Topology: не применяется. Итог — один публичный API и один алгоритм вместо
набора исследовательских операций; отдельный ARM runtime не добавлен.

**S2 — артефакты исследований.** Граница: `reports/` учебного варианта.
Удалены сохранённые измерения, PDF, сборочные TeX-артефакты и анализатор,
требовавший внешние модели/данные/модули. Они не являются зависимостью
`round_fp16`, pytest или wheel. Исходные отчёты доступны в первоначальной
папке и в истории Git. Последствие — учебная копия не пересоздаёт исследование.
Проверка: сборка Docker из собственного контекста и wheel без внешних папок.
Риск низкий и обратимый. Topology: не применяется. Итог — нет внешних
исследовательских зависимостей и старого Ruff E402 из анализатора.

Сохранены обязательные dtype/device проверки, поддержка неконтинуальных
входов, настоящий Git и баг-история. Не заменены алгоритм округления,
проверки ошибок или история команды имитациями.

## Проверка исправлений 23 октября 2026 года

- База обоих этапов Docker — **ubuntu:24.04**, подтверждена пользователем как
  требование преподавателя. Старый образ практики 2025 года исключён.
- Cortex-M55 остаётся **обязательной** Docker-проверкой: один fp16.h используется
  и host-расширением, и arm-none-eabi-g++ с `-mcpu=cortex-m55`. Это кросс-компиляция,
  не запуск ARM-объекта на компьютере и не отдельная реализация операции.
- Сборка использует обычный `pip wheel . --no-deps`, с изоляцией. Linux build
  dependencies выбирают официальные CPU-wheel torch для Python 3.11/3.12,
  x86_64/aarch64. Их четыре ссылки проверены ответом HTTP 200. На Mac — PyPI.
- Smoke строит wheel прямо в dist/, greps платформенный тег и устанавливает
  dist/*.whl в свежий venv. Отдельный Python-процесс сначала импортирует
  stm32nn без предварительного импорта torch, затем идут demo и pytest.
- macOS arm64: полный исправленный smoke завершился `7 passed` и `OK`;
  независимый импорт из нового venv успешен; миллион случайных значений
  точно совпал с PyTorch. Ruff проходит.
- Состояние Linux x86_64 и Docker проверяется опубликованным workflow:
  https://github.com/NickElixir/FSE4AI-stm32nn/actions
  Для сдачи проверяйте зелёный прогон именно сдаваемого коммита, а не старого.
  Прежние ARM64 Docker-результаты от 22 октября не заменяют эту проверку.

## Публикация и комплект сдачи

Текущий аккаунт имеет READ-доступ к velosipedistufa/FSE4AI-stm32nn, поэтому
безопасный путь публикации — fork NickElixir/FSE4AI-stm32nn и pull request.
Изменение исходного master требует прав или принятия PR владельцем.
Локальный master и ZIP должны содержать итоговый код; в ZIP обязательно .git.
Архив для сдачи называется nikolaj.luczenko.zip (логин использован в предыдущих
сдачах этого курса). Отправка в LMS здесь не выполняется.

Предыдущие подтверждённые числовые проверки сохранены: 63 488 конечных кодов
binary16 точно воспроизводятся, включая знак нуля; cProfile описан в NOTE.md.
Отсутствие необязательного NumPy может давать предупреждение PyTorch;
этот проект NumPy не использует.

Исходный исследовательский проект не изменён. Его старое окружение было удалено
отдельной, явно разрешённой пользователем очисткой диска. Учебное окружение
сохранено. Исходное состояние учебного Git доступно по коммиту 1929003;
сборочные результаты удаляются make clean, а не очисткой пользовательских папок.
