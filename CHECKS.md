## Почему учебный вариант меньше

**S1 — основной пакет.** Граница: `src/stm32nn/__init__.py`, `ops.cpp`.
Убраны дополнительные conv/pool/linear, int8, layout, compare, export-check и
stochastic API из этого варианта. Их потребители — исследовательские отчёты
и демо, а контракт финального проекта — `round_fp16`. Пользователь подтвердил
сохранение только float32 → float16 → float32. Исходный проект со всеми
функциями сохранён отдельно. Цена старого варианта — отдельные контракты и
непроверенные числовые алгоритмы, не нужные для сдачи. Единственный оставшийся
алгоритм находится в `fp16.h`; Python только экспортирует C++-функцию.
Последствие: исследовательские скрипты нельзя запускать из учебного пакета.
Проверка границы: тесты установленного wheel, exact equality с PyTorch,
ошибка из C++, demo и компиляция общего ядра под Cortex-M55. Риск ограничен
новой самостоятельной копией; восстановление — исходная папка или Git.
Topology: не применяется. Итог — один публичный API и один алгоритм вместо
набора исследовательских операций; отдельный ARM runtime не добавлен.

**S2 — артефакты исследований.** Граница: `reports/` учебного варианта.
Удалены сохранённые измерения, PDF, сборочные TeX-артефакты и анализатор,
требовавший внешние модели/данные/модули. Они не являются зависимостью
`round_fp16`, pytest или wheel. Исходные отчёты доступны в первоначальной
папке и в истории Git. Последствие — учебная копия не пересоздаёт исследование.
Проверка: сборка Docker из собственного контекста и wheel без внешних папок.
Риск низкий и обратимый. Topology: не применяется. Итог — нет внешних
исследовательских зависимостей и старого Ruff E402 из анализатора.

Сохранены обязательные dtype/device проверки, поддержка неконтинуальных
входов, настоящий Git и баг-история. Не заменены алгоритм округления,
проверки ошибок или история команды имитациями.

## Результаты

Проверено 22 октября 2026 года:

- **macOS arm64 / Python 3.12.5 / torch 2.12.1:** сборка и установка wheel,
  7 тестов из нейтрального каталога, Ruff, demo с 1 млн случайных значений.
- **macOS smoke:** два новых venv, установка wheel, demo, 7 passed, `OK`.
- **Дополнительная числовая проверка:** все 63 488 конечных кодов binary16
  точно сохраняются, включая знак нуля.
- **Linux ARM64 / Docker / Python 3.11 / torch 2.12.1+cpu:** двухэтапный образ
  собран; 7 passed; demo с 1 млн значений прошёл. В runtime нет g++ и /src.
- **Cortex-M55:** общий fp16.h успешно скомпилирован arm-none-eabi-g++ с
  `-mcpu=cortex-m55 -mthumb -mfloat-abi=hard`; это проверка компиляции,
  а не выполнение на микроконтроллере.
- **Последняя builder-сборка:** после уточнения зависимостей упаковки и
  минимизации заголовков снова собраны Cortex-M55 object и Linux ARM64 wheel.
- **Ограничение локальной проверки:** дополнительный Linux smoke с двумя
  свежими venv не удалось завершить: при экспорте builder-образа закончилось
  свободное место на Mac. Это не успешный Linux F2-прогон; его нужно выполнить
  через `./tools/smoke.sh` или CI на машине с достаточным местом.
- **Linux x86_64 и hosted CI:** подготовлены команды и workflow, удалённый
  запуск не выполнен. Они не выдаются за уже пройденные проверки.

PyTorch при отсутствии необязательного NumPy печатает предупреждение;
эти операция и тесты NumPy не используют. Тесты завершились успешно.
Публикация, push в удалённый default branch и отправка в LMS не выполнялись.

Отмена этой учебной переработки не требует изменений исходного проекта:
он сохранён в соседней папке; в новой копии исходное состояние также доступно
по коммиту 1929003. Не используйте общий `git clean` для очистки пользовательских
проектов. Артефакты учебной сборки удаляются `make clean`.
